# 发布与更新日志规范

- 大版本更新与新增功能：逐项说明用户能做什么。
- 重要问题修复：写明解决的问题及对用户的影响。
- 小修小改与实现细节：合并为“细微优化”，不罗列字号、像素、测试数量等细节。
- 本地预览尚未公开时可合并到下一次公开版本；旧的已发布历史保留。
- 发布前先向用户提供可运行版本和简洁更新内容，等用户明确确认后再推送 GitHub、创建标签或发布 Release。

版本号保持 VERSION、Info.plist 和应用显示一致。确认后把 CHANGELOG.md 中“待确认发布”改为实际发布日期，再运行测试和打包。

GitHub Release 工作流使用 scripts/release-notes.sh 提取当前版本的条目，不再复用固定产品介绍。手动发布同样使用该脚本的输出。
